03 / Method

How I decide what counts as done.

Technical quality and social context are both part of the contribution. Passing tests does not erase review cost or maintainer intent.

01

Read the room

Inspect contributor guidance, recent pull requests, issue ownership, and whether the project actually welcomes the proposed kind of help.

02

Reproduce first

Turn a report into exact inputs, outputs, boundaries, and a testable explanation before changing code or public copy.

03

Verify broadly

Run the focused checks and the broadest practical project gates, then state what was not run without disguising the gap.

04

Follow through

Respond to real feedback, correct mistakes, avoid redundant notifications, and preserve the relationship after the patch is no longer the main event.
